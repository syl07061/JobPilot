# JobPilot MVP Roadmap

目标：BOSS原生条件初筛 → 信息采集 → 数据库去重 → AI智能复筛 → 推荐展示。AI判断依据为个人简历、求职偏好、完整JD。当前实现独立列表、薪资还原和自动逐个读取面板JD。

## Phase 0 — 工程与采集接口验证

- [x] 保留FastAPI / React / TypeScript工程、健康检查和配置。
- [x] 独立读取参数、任务、岗位视图和来源契约。
- [x] 自主实现公开CDP客户端，不调用BossHunter采集器/HTTP/Runtime。
- [x] 离线DOM与实际本机WebSocket协议验证，不访问真实BOSS。
- [x] 保留此前BossHunter实现和字段样本作为历史对照，不作为新任务来源。

## Phase 1 — 原生条件、岗位采集与真实数据分析（WIP）

- [x] 用户手动在专用Chrome设置原生条件，JobPilot仅设置页数。
- [x] 当前列表DOM读取、原文、标签、链接及缺失字段展示。
- [x] 正常滚动、确认新增批次、任务内重复链接合并。
- [x] 原始DOM JSON、复制、停止、限制/空壳/页面变化等状态处理。
- [x] 用户主动点击获得30条真实列表记录；开发不自动多轮检索。
- [x] 实际字体逐一验证数字映射，30条薪资还原，原始值保留。
- [x] 当前右侧职位描述匹配读取、单岗位按需读取及明确未读取状态；真实1条503字JD验证。
- [ ] 根据真实页面反馈完善容器/字段识别及传统分页支持。
- [x] 自动逐个打开岗位面板获取JD，已有列表补齐、阶段进度、逐岗位状态及停止；离线真实CDP点击验证。
- [x] 每日额度可配置、开始前显示已用/剩余、操作前重新核对；保存不清空计数、不自动恢复任务。
- [x] 用户触发真实自动JD，任务已保存4条描述；定位并修复列表/详情标题后缀不同造成的误判。
- [ ] 标题匹配修复后继续验证完整批次稳定性，保留额度，不自动多轮平台测试。
- [ ] 评估独立详情页及其他页面形态支持。

“页”目前是一次已加载岗位批次，不保证每批固定条数。没有新URL不算下一批。专用字体薪资只对已核对资源还原；自动JD保持岗位之间至少3秒间隔，每个岗位最多点击一次，描述必须与岗位URL及已记录的选中卡片对应；列表/详情标题允许不同并分别保留。列表/刷新/详情共用可配置的每日额度（默认20次），超时或限制立即停止并保留部分结果；配置不清空已用量，不改变风险停止策略。

## Phase 2 — 存储、增量与去重（Planned）

- [ ] JobPilot自有SQLAlchemy模型与SQLite会话。
- [ ] 跨任务增量采集、来源标识去重与内容更新。
- [ ] 区分历史记录、当前页面记录及实际新增，建立事务与完整性测试。

当前任务JSON和跨批次链接合并不是本阶段完整岗位数据库能力。

## Phase 3 — 简历、求职偏好、AI复筛与多维匹配（Planned）

- [ ] 授权简历解析与偏好管理。
- [ ] 用个人简历、偏好和完整JD共同判断，不仅依赖标题。
- [ ] OpenAI兼容模型适配、解释、缺失证据及异常处理。
- [ ] 多维评分与可复核结果；本轮不设计复杂模型或执行AI。

## Phase 4 — 推荐前端与任务管理（Planned）

- [ ] 推荐列表、排序、评分解释与人工复核。
- [ ] 完整工作流管理；当前单参数读取页面仅为基础入口。
- [ ] 端到端可靠性与隐私验证。

## 持续边界

不自动登录、修改指纹、拦截安全资源或绕过验证码。不自动沟通、投递或发送简历。不修改BossHunter源码、配置或清空其访问账本。新模式保留JobPilot自己的低频、互斥及当日预算；异常立即停止，不借独立实现规避平台限制。仅在用户明确要求时提交或推送Git。
