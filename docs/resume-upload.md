# 简历上传与版本展示

工作台新增“简历上传”标签。选择PDF或Word文件后点击上传，成功后展示版本号、原文件名、格式、大小、上传时间与下载入口，最新上传排在前面。每次成功上传新增一个版本，同名、相同内容文件也不覆盖或丢弃旧版本。

支持`.pdf`、`.docx`、`.doc`上传，每个文件最多10MB；检查PDF标识、DOCX包内Word文档标识、DOC的OLE Word命名流。空文件、格式不符、超限或已识别的加密/损坏文件会拒绝；DOCX限制展开体积并拒绝宏包。格式检查不是完整正文解析，也不是病毒扫描。上传与下载本身不调用AI；新增独立“解析最新简历”按钮处理文字版PDF/DOCX并维护个人档案，旧DOC解析需另存格式。没有文档内嵌预览或岗位评分。

## 存储

- `data/resumes/files/<UUID>.<扩展名>`：原件，保存完整上传字节，不使用用户文件名作为路径。
- `data/resumes/versions.db`：独立SQLite版本元数据，通过SQLAlchemy维护；含UUID、递增版本号、原文件名、格式、大小、UTC上传时间及SHA256。
- 首次读取版本列表时创建存储目录与元数据表；上传后才创建原件。重启后列表仍可读取。
- 此数据库独立于未来岗位库，不使用当前为岗位库预留的`DATABASE_URL`。已有模型配置仍在`data/settings/model.json`，没有迁移或修改。

上述文件均位于Git忽略的`data/`目录。上传内容不发送给AI或BOSS、不写入正常日志。所有API仅供本机开发使用；下载返回attachment、no-store与nosniff头。原件没有加密，应由本机用户控制目录访问。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| `POST /resumes` | multipart/form-data，字段file；成功201返回版本元数据 |
| `GET /resumes` | 返回items，版本号倒序 |
| `GET /resumes/{UUID}/download` | 下载该版本原件；不存在404 |

前端代理路径均增加`/api`。无效格式422、超限413；读取或保存异常明确报错，不自动重传。请求体亦有10MB加必要表单开销的限制，含无Content-Length请求。客户端上传超时后可以刷新列表核对，不以重传猜测成功与否。

上传/列表响应的`uploaded`及`parsed=false`只描述文件保存，不是历史解析结果清单。前端通过独立profile接口标记当前档案来源，解析时仅处理最新上传并维护唯一生效档案。当前没有删除或手动切换生效历史版本功能。参见[最新简历解析](resume-parsing.md)。

## 验证

测试使用合成PDF、DOCX及OLE Word容器，不使用真实个人简历。覆盖格式检查、逐字节下载回读、重启读取、同名/并发版本、路径处理、上传及请求体超限、跨站写入拒绝。界面演示覆盖两次同名上传、倒序版本、最新标识、下载链接及切换标签后重新读取；没有对外请求或真实用户文件上传。
