# 解析最新简历与唯一生效档案

简历文件保留上传历史，**结构化解析结果仅维护一份当前生效档案**。SQLite适合关联来源版本并用事务替换档案；文件系统继续保存原件，不另外维护每个历史版本的解析JSON。

## 流程

在“简历上传”页点击“解析最新简历”，后端锁定当时最新上传版本，检查文件哈希，本地提取文字，然后通过配置的OpenAI兼容`/chat/completions`调用模型。提取的简历文字会发给所配置服务并可能产生API费用。仅点击按钮才发起，不因上传、查看状态、切换标签或服务重启自动调用。

首版提取文字版PDF和DOCX：PDF逐页检查文字，1–20页；DOCX按文档XML读取段落、表格和文本框文字，并补充页眉页脚。超过40000字符、文字过少、乱码或无文字页面时停止，不静默截断，不启用OCR。旧DOC仍可上传保存，解析时提示另存DOCX或PDF；没有安装或自动执行Office转换器。复杂排版可能影响阅读顺序，用户需核对模型结果。

模型返回字段：姓名、邮箱、电话、所在地、概述、技能、教育、工作、项目、证书、语言。教育/工作/项目统一含organization、title、start_date、end_date、description。缺失标量为null，列表为空；不推断年龄、经历年限、求职偏好或额外事实。简历正文视为不可信文档，系统提示要求忽略其中指令，不访问外部链接。档案经JSON及Pydantic校验后才接受，空结果、额外字段、截断输出均拒绝。

当前提示词要求事实提取，但未明确要求逐条保留完整经历原文，模型可能概括描述。前端直接展示已保存字段，不再次摘要或截短。完整保留技术细节、量化成果和原文证据的策略仍待完善；不能将当前档案当作无损的简历文本副本。

## 一致性

- 每次新解析只处理最新上传，不重新解析全部历史版本；同一后端进程只允许一项解析运行。
- 解析失败、超时、网络错误或输出校验失败，保留旧档案。错误只保留安全原因码和提示，不保存模型错误正文或凭证。
- 发布时通过SQLite写事务重新检查最新上传ID。解析期间上传了新文件，旧任务的结果丢弃；不得反向覆盖最新资料。
- 成功后原子替换id=1的档案，并记录来源文件ID、版本、文件名、模型ID和时间。旧解析结果不另建版本记录；上传原件仍全部保留。
- 旧档案尚在使用但有更新文件时，前端明确显示“最新上传尚未生效”。结果由AI提取，需用户核对。
- 当前只记录最近一次解析尝试的状态；重启后运行中任务标记中断，不自动重试或扣费。

## 存储与API

沿用`data/resumes/versions.db`，新增`current_resume_profile`和`latest_resume_parse_attempt`表；不破坏原版本表。未保存简历原文提取副本、模型原始响应或API Key到这些表。Key仍只来自后端模型配置服务。

| 接口 | 用途 |
| --- | --- |
| `POST /resumes/parse-latest` | 显式启动解析，202返回状态；无简历/无模型配置时拒绝，已有任务409 |
| `GET /resumes/profile` | 返回当前档案、最近解析状态、最新上传版本及is_current；不调用模型 |

请求90秒超时，不自动重试，拒绝HTTP重定向，响应上限512KB。火山方舟请求关闭深度思考以提取JSON；其他兼容服务只使用通用字段。遇不兼容参数明确报错，不用多次付费请求猜测协议。

该版本不执行岗位复筛或评分。后续评分应记录档案来源版本，当前没有自动重算旧评分。
