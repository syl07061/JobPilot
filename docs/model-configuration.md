# 模型配置与工作台标签

工作台分为四个标签：配置、筛选条件、采集结果、简历上传。配置中包含每日读取额度和大模型设置；筛选条件保留原有城市、区域及复选检索；结果中展示任务进度、岗位、JD及来源JSON；简历标签展示上传文件的版本信息。切换标签不清空筛选条件、不停止任务；检索成功启动后自动进入采集结果。

简历标签分为三个独立卡片：上传与解析（两步操作、费用说明和解析状态）、当前个人档案（基本信息、技能、教育/工作/项目分区及来源版本）、历史简历版本（最新上传及档案来源标记、原件下载）。桌面下档案与版本并列，窄屏自动纵向排列；查看或切换卡片不触发模型调用。

模型设置包含OpenAI兼容服务的Base URL、模型名称（模型ID）和API Key。Base URL应按服务商要求填写，是否包含`/v1`取决于服务；不要填写带Key的查询参数或用户名密码。保存只检查格式，不发送模型请求、不验证连接、不自动复筛，也不消耗模型费用。简历页面的“解析最新简历”才会读取该配置调用模型。

接口：`GET /settings/model`、`PUT /settings/model`（经前端代理时以`/api`为前缀）。GET和PUT响应只返回base_url、model、has_api_key、configured、source，不回传Key及其片段。configured仅表示三个字段齐全，不表示连通性验证通过。

- `api_key`省略、null或空字符串：保留原Key。
- 提交非空`api_key`：替换Key；成功或失败后前端清空密码框。
- `clear_api_key=true`：明确清除，包括覆盖环境变量中的旧Key；不能同时传入新Key。
- 模型配置校验错误不回显请求input，避免Key或URL中的凭证出现在错误响应。

未保存本地配置时使用`.env`或进程环境中的`AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`。首次保存后以`data/settings/model.json`为准，重启后仍有效；Key留空会保留当前生效的Key。损坏文件明确报错，不当作空配置覆盖。

配置文件**未加密**，仅用于当前本机开发环境；`data/`由Git忽略。Key不写入浏览器localStorage、URL或正常日志，不随源码提交。最新简历解析已从后端配置服务读取凭证并调用模型，不将Key发给前端；配置保存不会触发调用。当前未提供单独连接测试或AI岗位评分。
