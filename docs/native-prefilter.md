# BOSS 初筛：工作区域与复选

JobPilot独立CDP读取器支持先筛选、后采集：**城市、工作区域（行政区）、求职类型、薪资待遇、工作经验**。城市单选，其余使用复选框；同一条件内按“任一满足”（OR），不同条件之间同时满足（AND）。关键词仍在专用Chrome的BOSS页面手动输入。

经验与行政区使用BOSS原生多选。求职类型、薪资在当前BOSS前端中为单选，JobPilot按两者的组合依次检索，再取岗位并集、按公开岗位链接去重。不会把逗号拼接给不支持多选的单选参数，也不会先放宽条件采集全部岗位再在本地伪造初筛。

例如：薪资选10-20K和20-50K、经验选“经验不限”和“1-3年”、行政区选浦东和杨浦，会执行2组搜索；每组经验及区域均为两项原生多选。再选全职和兼职则变成4组。切换城市清空原区域。不限与具体选项互斥；“经验不限”（101）是一类岗位要求，可以与1-3年（104）同时选，不等同于不筛选的“不限”（0）。

## 使用方式

1. 在项目根目录运行`start.bat`，在专用Chrome手动登录并搜索关键词，只保留一个BOSS搜索结果标签页。
2. 在JobPilot选择城市、行政区及其他复选条件，设置**每组**读取批次，确认组合数、列表次数和剩余额度。初次验证建议1组、1批。
3. 点击“开始读取”。脚本在同一标签页按计划串行导航，每组一次；保留公开`query`关键词，清除其他旧条件（包括商圈、地铁）。
4. 逐组核对城市及实际选中项的编码集合，要求完整相等，顺序可不同；全部匹配后才读取该组列表及JD。任务面板显示总体请求、当前组和实际回显，各组结果单独保留。

运行时不根据列表薪资或经验在本地模拟筛选。BOSS原生条件的具体含义由平台决定，不等同于对薪资数字做精确包含匹配。详细工作地址目前只采集展示，不作为此次城市筛选的替代。

## 选项与传参证据

2026-11-19只读核验真实页面：`.filter-select-dropdown li`的公开`ka`属性提供选项编码，按ka语义定位对应菜单，避免兼职附加控件造成下标错位。`.current-select`可能只显示“工作经验(2)”等计数，实际值从`li.active`获取。当前真实页面同时选中经验104、105，公开URL为`experience=104,105`。

城市来自不带认证的公开`/wapi/zpCommon/data/city.json`，当次374项（含全国）。行政区来自页面实际请求的公开`/wapi/zpgeek/businessDistrict.json?cityCode=...`，只导出`businessDistrict.subLevelModelList`的name/code，核对目录所属城市；上海当次16区。`.city-area-label`中的`close_select_area_310115`对应“全浦东新区”，公开URL为`multiBusinessDistrict=310115`。多区用逗号连接，最多9项；本轮不开放商圈、地铁或详细地址筛选。

同时只读核对当前页面已加载的公开业务资源`zhipin-geek-spa/web/v6825/static/js/job~1.079cb0ad.js`：jobType及salary的multiple为false，experience为true；区域控件在`job~0.5650fac1.js`中将multiBusinessDistrict作为逗号分隔的区域集合处理，上限9。仅据此确定公开参数语义，未复制其实现，不读取框架私有状态或安全脚本。

| 条件 | 公开搜索参数 | 当次实际DOM选项 |
| --- | --- | --- |
| 城市 | city | 公开目录编码，例如上海101020100、北京101010100 |
| 求职类型 | jobType | 不限0、全职1901、兼职1903；未擅自添加菜单没有的“实习” |
| 薪资待遇 | salary | 不限0、3K以下402、3-5K403、5-10K404、10-20K405、20-50K406、50K以上407 |
| 工作经验 | experience | 不限0、在校生108、应届生102、经验不限101、1年以内103、1-3年104、3-5年105、5-10年106、10年以上107 |
| 工作区域 | multiBusinessDistrict | 当前城市公开目录中的行政区编码，如浦东新区310115、杨浦区310110；逗号分隔 |

选“不限”时不附加相应URL参数。编码来自实际页面，每组仍须由实际DOM的选中编码集合核验；不能仅凭URL里有参数就认为平台应用成功。BOSS改变控件、编码或忽略任一选择时，停止全部剩余组合，保留已取得的结果。

## 接口与记录

`GET /search/filter-options?city=101020100`返回按城市缓存的目录；无缓存或`refresh=true`时读取实际筛选DOM、公开城市和区域目录，不点击、不导出岗位、不扣读取额度。缓存version=2，旧版缓存自动失效。任务执行时重新核验实际选项与区域所属城市，缓存不能绕过验证。

```json
{
  "max_pages": 1,
  "filters": {
    "city": "101020100",
    "job_type": ["1901"],
    "salary": ["405", "406"],
    "experience": ["101", "104"],
    "regions": ["310115", "310110"]
  }
}
```

上例提交`POST /search/tasks`，执行2组、每组1批。旧单值字符串仍可用，regions缺省为不限；不传filters仍保持读取当前页面的行为。空复选数组、不限与具体值混选、不属于当前城市的区域会拒绝；经验101可与104同时选。

`phase=filters`表示正在应用当前组；`applied_filters`保存总体requested、active_group、group_index/group_count、effective及verified。`search_groups`记录逐组结果，`counts.pages_requested`为每组批次×组合数，`pages_read`累加实际批次。原始DOM快照带组号与组内批次；聚合去重不删除实际快照，不使用历史任务填充。

`filter_failed`区分选项不支持、控件无法识别、回显未匹配；每组`no_results`仅用于核验后页面明确无职位。全部组合都无结果，整体才为no_results。空壳为load_failed；登录、验证码或访问限制为platform_restricted。任一失败、额度耗尽或用户停止都会停止后续组合，不重复该组、不继续碰运气。先前组的有效结果保留。

**每组**搜索加载和首批共计1次，后续每批和需要打开的JD共用原账本。跨组相同岗位只保留一条；本任务已读JD跳过，不再次计JD读取。每组批次×组合数总共不得超过20批；沿用低频、互斥和每日额度，前端显示列表预算，JD次数取决于实际结果，额度不足即停止。参数修改不清空计数、不自动恢复任务；“开始读取”建新任务，“自动补齐”仍只补原任务JD，不自动重跑未执行的组合。

URL快照去除查询和片段；只单独保存公开关键词/条件及岗位DOM，不保存认证参数、Cookie、Token、浏览器存储或聊天内容。不修改指纹、不绕过验证，不使用BossHunter代码或配置。
